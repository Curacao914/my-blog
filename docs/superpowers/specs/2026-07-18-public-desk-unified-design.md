# 公开站与工作台统一前端设计规格

## 目标

在不改变现有功能、路由、权限、数据语义和后端工作流的前提下，重新设计公开站与 `/desk` 工作台的信息层级、布局、排版和交互反馈，使整站形成简约但不简单、克制而完整的产品体验。

本轮不增加装饰性功能，不制造新的内容入口，不把设计说明、架构解释、实现状态、开发术语或助手式文案放进产品界面。

## 已确认的基线

- 开发分支为 `codex/homepage-phase1`，不得直接修改或推送 `main`。
- 本地开发分支从旧提交 `13ffafa7` fast-forward 到当前 `origin/main` 的 `59481b16`，保留了最新前端汇总、阅读性能、认证稳定性和 Clerk 账号重绑定修复。
- `54f8ed73` 是多轮公开站、macOS 风格 Shell、主页和工作台视觉实验进入 `main` 的汇总提交。
- 历史 `frontend-polish`、`macos-glass`、`macos-system-shell` 和 `macos-home-desktop` 分支是迭代记录，不再整支合并或作为施工基线。
- NotionNext 继续承担旧文章与兼容路由；新设计不得以全局覆盖的方式破坏其主题页面。

## 设计原则

### 目的与层级

每个页面首先回答用户当前在哪里、最重要的内容是什么、下一步能做什么。首要操作直接可见，次要管理动作通过菜单、抽屉或详情逐步展开。界面元素必须有明确用途，不能用装饰填补空白。

### 简约但不简单

简约来自清晰的顺序、克制的密度和一致的组件行为，不来自隐藏必要信息。高频操作减少步骤，低频设置适度收纳，危险操作保持清晰确认。信息密集页面允许更紧凑，但不牺牲可读性和操作目标尺寸。

### 产品文案边界

界面只使用完成任务所需的名称、状态、提示和错误反馈。禁止出现：

- 设计理念、技术架构和数据来源解释；
- “这里用于”“本页面实现”“系统将会”等说明书式文案；
- 开发阶段、部署状态、占位承诺和助手对用户的说明；
- 为填充版面而添加的口号、泛化 AI 文案或重复副标题。

空状态只说明当前事实，并提供一个真实可执行的下一步。错误反馈说明发生了什么以及用户可以采取的动作，不讲内部实现。

### Apple 风格交互约束

- 按钮在 pointer-down 时提供轻微即时反馈，操作仍在 pointer-up/click 时提交。
- 只有可触摸、可拖拽或可逆的对象使用弹簧和速度衔接；普通导航与内容出现不添加弹跳。
- 抽屉、弹层和菜单从触发源或一致方向出现，并沿同一路径退出。
- 用户可在过渡期间继续操作；不得用动画锁住输入。
- 动效只使用 `transform` 和 `opacity` 等合成友好属性；玻璃表面变化保持短促克制。
- `prefers-reduced-motion` 使用静态状态或短交叉淡入；`prefers-reduced-transparency` 使用更实的背景；高对比模式提供明确边界。
- 不增加全屏液态背景、持续循环动画、无功能的视差和大幅弹性效果。

### 视觉语言

- 延续温暖白、淡蓝绿、深墨绿、衬线标题、大圆角和柔和阴影。
- 玻璃材质用于导航、工具条、弹层等浮动功能层，不在多层浅色玻璃之间继续叠加。
- 大表面使用更稳定的背景和更深的分离阴影，小控件使用更轻的材质。
- 标题使用尺寸相关的负字距和紧凑行高；正文保持舒适行高；小号文字不使用过紧字距。
- 以 rem、clamp 和内容约束实现响应式排版，避免固定像素导致文本放大后破版。

## 信息架构

### 公开站

公开站保留现有路由和内容来源，统一为三层结构：

1. 全局层：品牌入口、主导航、搜索和账户入口；
2. 页面层：当前页面标题、必要筛选或上下文；
3. 内容层：文章、分类、集合、工具或个人信息。

主页是内容与真实工具的入口，不是个人宣传牌。首屏优先呈现精选/最近内容、搜索和高频入口；分类与次要入口随后出现。内容库、搜索、归档、分类、标签、About 和阅读页共享导航、页面宽度、排版节奏和反馈规则，但不强行使用相同布局。

### 工作台

工作台保留全部现有路由、权限过滤和真实功能，导航按任务心智重新组织：

- 安排：Today、Tasks、Notes；
- 阅读与知识：Reading、Materials；
- 创作：Courses、Writing、Publishing；
- 管理：System 及现有管理员功能。

最终标签以现有 `deskNav` 和权限契约为准，重组不得绕过 `NAV_PERMISSION`，不得使无权限页面通过视觉入口重新暴露。

桌面端使用稳定侧栏和独立内容滚动；移动端使用可关闭、可按 Escape 退出、焦点可管理的抽屉。顶栏只承担当前位置、页面级主操作和账户入口，不重复侧栏内容。

## 组件边界

### 共享设计基础

建立作用域明确的设计变量和基础状态：颜色、字体、间距、圆角、阴影、材质、焦点、按下、禁用、错误、加载和 reduced-preference。新规则只作用于 law-tech 公开站和工作台，不全局重写 NotionNext。

### Public Shell

`PublicHeader` 负责公开导航、搜索入口与账户状态；页面内容组件不自行复制全局导航。移动端导航必须在不丢失路由的前提下收纳，并保持当前页面可识别。

### Desk Shell

`DeskShell` 只负责权限过滤后的导航、侧栏/抽屉状态、页面标题区和滚动容器。Today、Reading、Courses 等业务组件继续负责自身数据和操作，不把业务请求移入 Shell。

### 表面与交互原语

优先复用小型、无业务语义的模式：按钮、图标按钮、卡片、工具条、弹层、菜单、分段控制、状态标签、空状态和反馈消息。不得为了视觉统一引入大型 UI 库。

## 大闭环

### 闭环 0：安全基线

确认开发分支与 `origin/main` 对齐；记录历史分支分类；运行当前关键 Shell/主页测试和构建，区分已有失败与新增回归。该闭环只建立可信施工基线。

验收证据：Git 状态、精确基线提交、聚焦测试结果、构建结果。

### 闭环 1：设计基础与双 Shell

统一设计变量、排版、材质、控件状态、焦点、降级偏好；完成 Public Shell、Desk Shell、桌面侧栏、移动抽屉和账户入口。保持现有导航目标、权限和会话行为。

验收证据：Shell 合同测试、键盘与移动状态测试、相关认证测试、构建。

### 闭环 2：公开站

完成主页、内容库、搜索、分类、标签、归档、About、工具与阅读表面。删除解释性文案；让首屏、筛选、卡片、长文阅读和错误/空状态形成一套完整体验。

验收证据：现有公开页面测试、产品文案静态门禁、响应式关键状态、构建和 Preview 路由遍历。

### 闭环 3：工作台框架

完成工作台导航重组、页面标题区、滚动关系、通用操作层级和移动导航，不改业务组件请求与数据状态。

验收证据：导航与权限测试、Desk Shell 测试、关键路由渲染、构建和 Preview 导航遍历。

### 闭环 4：核心工作流

按以下组别逐一接入统一设计，每组完成后仍可独立使用：

1. Today、Tasks、Notes；
2. Reading、Materials 与阅读器；
3. Courses 与课程状态/控制；
4. Writing 与 Publishing；
5. System、账户与管理员设置。

只改变信息组织、控件呈现和反馈，不改变 API、保存时机、权限、所有权、可见性、发布、任务调度或课程状态机。

验收证据：每组已有聚焦测试、保存/恢复/错误路径、权限状态、构建；涉及真实外部服务的行为明确标记为未验证或 Preview 验证。

### 闭环 5：全站收口

执行跨页面一致性、产品文案、键盘、焦点、响应式、降级偏好、长内容、加载、错误和空状态审查；运行完整必要测试与生产构建；在 Preview 检查公开站和工作台核心路径。

验收证据：`git diff --check`、最终测试集、生产构建、Preview 路由与关键工作流清单。Production 发布不在本轮自动授权范围内。

## 数据流与功能保护

- 页面继续调用现有 API、hooks 和 domain helpers；视觉组件不建立第二套缓存或数据源。
- 会话、权限、用户隔离、内容访问、发布、提醒、课程处理和 OpenClaw 行为不因前端重组而改变。
- 不使用 mock、示例或 fallback 数据制造成功状态。
- 删除或收纳控件前，必须确认它的路由、权限与业务调用已有等价入口。
- 涉及表单的视觉重排必须保留字段、校验、disabled/busy 状态、错误反馈和提交结果。

## 测试策略

- 先用现有合同测试锁定导航、Shell、主页、内容阅读、工作台和权限行为。
- 每个闭环只运行受影响的聚焦 Jest 测试；共享基础或 Shell 变化时补充最小合同测试。
- 不为纯 CSS 像素细节编写脆弱快照；测试结构、状态、可访问名称、权限与关键 class/attribute 契约。
- 每个大闭环末尾运行 `npm run build`；最终闭环运行完整必要测试集。
- 使用真实 Preview 做路由和关键交互验证；本地测试与 Preview 验证分开报告。
- 不因测试修改 `test-results/junit.xml`；若 Jest 生成变更，交付前恢复。

## 完成定义

一个闭环只有同时满足以下条件才算完成：

- 该范围内现有功能仍可操作，没有被视觉层遮挡、遗漏或改义；
- 桌面与移动布局均可用，键盘焦点和必要 aria 状态正确；
- 产品界面没有解释性、开发性或占位式文案；
- reduced-motion 和必要透明度降级有效；
- 相关测试通过，构建结果明确，Preview 状态如实标记；
- continuity 文档只在实际状态改变时更新，不把设计说明复制到产品界面。

## 非目标

- 不修改后端工作流、数据库 schema、权限模型或 API 语义；
- 不增加大型 UI 或动画依赖；
- 不复活历史 liquid-glass 实验或整支合并旧前端分支；
- 不重写成熟 NotionNext 文章渲染器；
- 不自动合并或发布到 `main` / Production；
- 不为了展示设计能力增加无实际功能的页面、动效或文案。
