# law-tech.dev 多用户工作区与私人配置

更新时间：2026-06-28

本阶段把原先的单管理员工作台改造成可邀请成员使用、同时保持私人数据与服务额度隔离的工作区。它是 Writing Studio、分享链接和后续协作能力的前置基础。

## 一、角色与账号状态

工作区只保留两种角色：

- `owner`：站点管理员。可以管理成员、站点连接、Notion/Algolia 同步和全站公开发布。
- `member`：受邀成员。只能使用自己的私人工作区以及管理员授予的功能。

账号另有三种状态：

- `pending`：已注册但尚未批准；
- `active`：可以进入工作台；
- `suspended`：账号保留但不能进入工作台。

管理员白名单仍通过 `CLERK_ADMIN_EMAILS` 或 `CLERK_ADMIN_USER_IDS` 识别根管理员。普通注册用户不会自动获得管理员角色。受邀邮箱注册后自动成为启用成员；未受邀注册则进入等待批准页。

## 二、权限

第一版按功能授予权限：

- `schedule`：Today、Tasks 与日程；
- `notes`：随手记；
- `reading`：阅读箱；
- `courses`：课程资料、课程 AI 与笔记库；
- `writing`：写作汇总及未来 Writing Studio；
- `reminders`：个人邮件提醒；
- `ai`：个人 AI 配置；
- `publish`：把内容发布到公开站点。

成员默认拥有私人功能，但默认没有 `publish`。管理员拥有全部权限。

权限控制需要同时存在于：

1. 页面入口与导航；
2. API 鉴权；
3. Repository 的 `owner_id` 条件；
4. Supabase RLS。

隐藏导航不等于权限控制，任何受保护 API 都不能依赖前端按钮是否可见。

## 三、身份切换

管理员可以从右上角账号菜单或成员管理页切换到某个启用成员的身份，用于检查：

- 该成员能看到哪些导航；
- 该成员自己的日程、笔记、课程和内容；
- 该成员的 AI、邮件与提醒设置；
- 被关闭权限时的真实表现。

身份切换使用绑定管理员 Clerk 用户 ID 的签名 HttpOnly Cookie。被测试身份不能看到管理员专属的“成员与权限”和“站点维护”栏目。退出测试身份后恢复管理员视图。

身份切换仅用于管理员测试，不是共享账号，也不改变 Clerk 登录身份。

## 四、私人数据所有权

以下数据必须按 `profiles.id` 隔离：

- `schedule_items`；
- `tasks`；
- `notes`；
- `captures`；
- `materials`；
- `reminders` 与 `reminder_preferences`；
- `course_jobs` 及其子记录；
- `content_items` 及其版本、权限、展示与素材；
- `user_integrations`。

浏览器本地缓存同样按有效 profile ID 命名。切换身份时不能把上一身份的 Today 或课程后台任务写入新身份的缓存。

旧数据迁移采用：添加可空 `owner_id` → 回填根管理员 → 更新代码 → 加索引与 RLS → 无空值时收紧为非空。迁移 SQL 位于：

```text
lib/db/migrations/20260628_multi_user_workspace.sql
```

## 五、个人 AI 与邮件服务

每个成员拥有自己的：

- OpenAI-compatible API 地址；
- API Key；
- 默认模型及日程、课程各阶段模型；
- Resend API Key；
- 邮件发件人；
- 收件邮箱与提醒策略。

成员不会回退使用管理员的环境变量 Key。只有 `owner` 在没有保存个人配置时，才可以兼容使用现有全局环境变量。

密钥使用 AES-256-GCM 在服务端加密，数据库不保存明文，前端只显示尾号提示。需要稳定配置：

```text
USER_SECRETS_ENCRYPTION_KEY
```

该值一旦用于生产保存凭据，不得随意更换；更换后已有密钥无法解密。

## 六、管理员成员管理

`/desk/system?section=members` 支持：

- 将邮箱加入授权名单；
- 设置首次权限；
- 批准、暂停或恢复成员；
- 修改显示名称与功能权限；
- 直接“以此身份查看”；
- 撤销尚未注册的邀请；
- 输入确认语后删除成员及其级联私人数据。

删除成员只删除本站工作区 profile 与受外键约束的私人数据，不会删除对方的 Clerk 平台账号。对方再次登录时会以未授权账号进入 pending 状态，除非管理员重新授权。

第一版的“添加授权”不会主动发送 Clerk 邮件邀请。管理员把注册链接发给对方即可；匹配授权邮箱后，注册账号会自动启用。未来可以在不改变权限模型的前提下接入 Clerk Invitation API。

## 七、账号入口与设置中心

工作台右上角不再放“首页 / 公开内容”快捷按钮，而是账号入口：

- 未登录：登录、注册并申请权限；
- 已登录：头像、基本信息、账号状态、设置、退出；
- 管理员：额外提供身份切换。

`/desk/system` 是统一设置中心，使用窄侧栏分区，而不是大块概念卡片：

- 账号；
- AI；
- 邮件发送；
- 提醒；
- 成员与权限（管理员真实身份）；
- 站点维护（管理员真实身份）。

## 八、部署步骤

1. 先在 Supabase 执行 `select id, clerk_user_id, role from profiles order by created_at;`，确认现有 profile 中恰好只有一个 `owner`；多用户迁移会在不满足时安全中止；
2. 先应用提醒迁移，再应用多用户迁移；
3. 配置 Clerk 管理员白名单，并确认它指向上述唯一 owner；
4. 配置稳定的 `WORKSPACE_SESSION_SECRET`；
5. 配置稳定的 `USER_SECRETS_ENCRYPTION_KEY`；
6. 在 Preview 创建一个测试成员；
7. 使用管理员身份切换逐页检查；
8. 使用真实第二个 Clerk 账号做交叉访问测试；
9. 测试通过前不要开放公开注册宣传，也不要合并 `main`。

生成推荐密钥：

```bash
openssl rand -hex 32   # WORKSPACE_SESSION_SECRET
openssl rand -hex 32   # USER_SECRETS_ENCRYPTION_KEY
```

## 九、双用户验收矩阵

必须验证：

- A 创建任务、笔记、阅读材料和课程，B 的列表中不存在；
- B 猜测 A 的记录 ID，API 返回 404 或 403；
- A 与 B 的浏览器缓存键不同；
- B 不配置 AI 时无法使用 A 的 Key；
- B 不配置邮件服务时无法使用 A 的 Resend Key；
- B 的提醒邮件只包含 B 的事项；
- 管理员切换为 B 时看到的内容与 B 实际登录一致；
- 暂停 B 后，B 只能进入账号停用页；
- 关闭某项权限后，对应导航消失且 API 同时拒绝；
- 删除 B 后，关联私人数据按外键策略清理；
- 只有拥有 `publish` 的用户才能公开发布，默认成员只能保存私人草稿。

## 十、当前边界

- 第一版是“同一产品、各自私人工作区”，不是团队共享空间；
- 暂不提供成员之间共享日程、课程或草稿；
- 外部微信/邮件采集仍绑定既有管理员入口，成员绑定外部账号需要后续 `integration_accounts` 阶段；
- Clerk Organizations 暂不引入，等确实需要团队协作再评估；
- Writing Studio 必须直接建立在本阶段的 owner 隔离模型之上。

## 十一、个人资料与站点配置边界

每个实际登录用户可以在“系统 → 账号”修改自己的显示昵称和头像 URL。头像图片继续由图床或其他远程主机保存，本站仅在 `profiles.avatar_url` 保存地址字符串，不保存图片二进制。URL 只接受 HTTP(S)。管理员以成员身份测试时，该自助入口只读，成员资料应回到“成员与权限”中管理，避免测试过程中误改。

Clerk 提供的姓名和头像只用于首次或空字段兜底，不能在每次登录时覆盖用户已经保存的工作区资料。

“站点维护”中的数据库、Storage、Notion、Algolia 和 Cron 属于部署级连接。Secret 继续放在 Vercel 或 Supabase，工作台只显示状态、重新检测和经过审查的同步操作。不得为了“所有设置都在网页里”而把全站密钥回传给浏览器。

双账户验收另增加：

- A 修改昵称和头像后，B 的个人资料不变化；
- 管理员切换为 B 时，账号资料编辑保持只读；
- 非 HTTP(S) 头像 URL 被服务器拒绝；
- 站点维护页不返回任何环境变量原值或密钥尾部之外的信息。
