# law-tech.dev 整站页面审计

更新时间：2026-06-28（第一轮 Preview 人工巡检已完成）

这份文档记录公开站点、私人工作台和遗留路由的产品定位。它用于避免后续功能开发时重复设计页面外壳、重新发明导航关系，或者把仍未完成的内部结构暴露为正式产品。

## 一、统一原则

1. 公开站点使用同一套暖白、浅蓝绿、深墨绿、衬线标题、克制玻璃质感与渐进展开方式。
2. 工作台使用 `DeskShell` 作为唯一主壳层；侧栏、移动端抽屉、顶部返回公开站点的入口保持一致。
3. 页面先说明用户在这里能完成什么，再呈现数据；开发进度、架构说明和助手对话不得进入前端文案。
4. 加载、空数据、失败和权限不足都是正式页面状态，不能只留下空白或裸字符串。
5. Notion 原生文章继续使用成熟的 NotionNext 阅读器；新工作台 Markdown 内容不强行转换为 Notion block，而是在视觉和目录行为上逐步靠拢。
6. 公开内容来自 Notion、live JSON 与 Supabase 的合并索引；不得为不同页面分别制造互相不一致的内容清单。
7. Algolia 是增强层，不是单点依赖。配置存在时检索正文；配置缺失或请求失败时退回本地统一索引。
8. 管理员同步必须显式触发、提供结果反馈，并同时处理 Notion 缓存、统一内容索引、公开页面重验证与 Algolia 索引。

## 二、公开页面

| 路由 | 定位 | 当前处理 |
| --- | --- | --- |
| `/` | 个人主页与主要入口 | 保留主页叙事；最近内容改为一张主卡与四张次卡，避免等宽卡片造成视觉失序。 |
| `/content` | 内容图书馆 | 四栏目首层、合集次层、内容末层；支持搜索、栏目、类型、标签与多种浏览入口。 |
| `/content/[...slug]` | 工作台发布内容阅读 | Markdown、目录、阅读进度、元信息与响应式侧栏。 |
| `/search` | 统一搜索 | 本地索引即时筛选；配置 Algolia 时追加正文命中结果。 |
| `/archive` | 时间归档 | 改用统一公开内容索引和新版公共页面壳层。 |
| `/category`、`/category/[category]` | 栏目浏览 | 改用统一公开内容索引，展示 Notion 与工作台内容。 |
| `/tag`、`/tag/[tag]` | 标签浏览 | 改用统一公开内容索引，按使用频率与内容数量展示。 |
| `/tools` | 可用工具入口 | 保留；只展示已经可用或有明确访问边界的工具。 |
| `/about` | 个人与项目介绍 | 保留；不承载开发日志。 |
| `/404`、`/500`、`/_error` | 错误状态 | 统一公共视觉、返回路径与搜索入口。 |
| `/sign-in`、`/sign-up` | Clerk 登录注册 | 保留独立、克制的鉴权页面。 |
| `/auth`、`/auth/result` | 已停用的 OAuth 遗留入口 | 明确跳转到不可用状态；不交换、保存、记录或通过 URL 传递授权令牌。 |
| `/s/[token]` | 分享链接 | 后端访问校验尚未完成，暂时呈现正式不可用状态，不显示令牌。 |

### Notion 文章路由

`/[prefix]/[slug]` 等现有 Notion 文章路由继续使用 NotionNext / react-notion-x 阅读器。这是有意保留的差异，不属于遗漏。迁移前必须先证明新阅读器可以完整承载 Notion block、图片、表格、书签、代码和内部链接。

| `/desk/reading` | 阅读箱 | 待读材料、来源与转入笔记。 |
| `/desk/courses` | 课程资料与生成工作流 | 维持现有可靠执行链路，不在本轮重构。 |

| `/desk/writing` | 写作汇总 | 不再展示概念卡片；汇总最近笔记、发布草稿与已发布内容。 |

| `/desk/system` | 连接与维护 | 展示数据库健康、权限边界、管理员内容同步与私人邮件提醒设置。 |
| `/desk/library` | 遗留别名 | 重定向 `/desk/materials`。 |
| `/desk/active` | 遗留别名 | 重定向 `/desk/today`。 |

## 四、遗留路由收口

- `/page/[page]` 重定向到 `/content`，不再返回旧主题文章列表。
- `/category/[category]/page/[page]` 重定向到对应栏目页。
- `/tag/[tag]/page/[page]` 重定向到对应标签页。
- `/search/[keyword]/page/[page]` 重定向到 `/search?q=...`。
- `/dashboard/*` 重定向到私人工作台；旧 NotionNext Dashboard 不再作为第二套工作台公开存在。

## 五、搜索与同步

### 搜索层次

1. 本地统一索引：标题、摘要、栏目、合集、课程与标签，永远可用。
2. Algolia：正文全文检索，可选增强；前端合并 Algolia 命中与本地结果并按链接去重。
3. 未配置 Algolia 时，页面不报错、不显示空白，并继续提供标题、摘要、栏目、合集、课程和标签搜索。

### 管理员同步

管理员在公共页或系统页触发同步后：

1. 清除 Notion 站点与根页面缓存；
2. 清除统一公开内容热缓存；
3. 重新读取 Notion、live JSON 与 Supabase；
4. 提取公开 Notion 文章正文，并为 Supabase 内容附带 Markdown 正文；
5. 在配置存在时更新 Algolia；Notion 成功读取后清理已下线的旧 Notion 索引，读取失败时不做破坏性清理；
6. 重验证首页、内容库、搜索、归档、栏目、标签与一批公开详情页面；
7. 返回内容数量、正文提取数量、索引数量、旧索引清理数量、提示和失败页面。

私密、密码、禁止索引和撤回内容不得进入 Algolia。撤回内容时同步删除对应 Algolia 对象。

## 六、巡检结论与仍需环境验证的项目

- 用户已完成第一轮整体前端检查，未发现明显阻断性问题；零散视觉细节统一进入 `docs/DEFERRED_POLISH.md` 后集中处理。
- Algolia 的 App ID、搜索 Key、管理员 Key 与 Index 是否已在 Preview 配置；未配置时本地搜索应继续工作。
- 管理员同步在 Vercel Serverless 环境中的缓存清除、超时和反馈。
- 新版归档、栏目和标签页面的多语言静态路径。
- `/desk/writing` 在笔记或内容接口单边失败时是否需要部分降级，而不是整页失败。
- Notion 原生文章与新版公共页之间的导航衔接。
- 分享链接后端校验与密码访问，未完成前不得恢复令牌展示。

## 七、后续开发顺序

1. 应用提醒设置迁移，完成 Resend 测试邮件和 Preview 手动 runner 验收。
2. 推进 Writing Studio：草稿、编辑、素材关联、自动保存、版本与转入发布。
3. 完成分享链接的 Token 校验、密码、有效期、撤销和访问记录。
4. 深化 System 设置并集中处理用户积累的视觉细节。
5. 只有公开站点、工作台、搜索和提醒链路稳定后，才评估合并到 `main`。
