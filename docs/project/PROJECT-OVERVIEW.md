# 项目概述

## 产品定义

Law-Tech 是一个同时面向公开内容和私人认知工作的个人系统：

> **公开个人站点 + 私人认知工作台 + 内容与自动化控制面。**

它不是纯博客、纯任务管理器或纯知识库。长期希望容纳法学、编程、日常生活和纯粹好奇，并让内容从捕捉、阅读、课程、思考、写作到发布形成可追踪的生长链。

三个长期判断标准：

1. **思考的痕迹**：不仅保存内容，还保存为什么在意、如何理解、后来在哪里使用。
2. **存在的证明**：课程、阅读、写作、事项和日记录留下真实生活锚点，不制造生产力羞耻。
3. **探索的可能**：法学是重要领域，但不是系统边界；技术、设计、历史、科学和未知主题都可以进入。

## 产品层次

### 公开层

- 首页、About、公开内容、文章、Archive、Category、Tag、Search、RSS、Sitemap；
- 保留 NotionNext 旧文章和路由兼容；
- `/content` 统一承载 Notion、Supabase、内容快照与后续发布内容；
- `/tools` 承载 OCR、引用和真正有日常价值的公开工具；
- 密码内容可以出现在目录，但不得进入公开搜索、RSS 或 sitemap。

### 私人工作台

- Today / Tasks：日期事项、每日概况、记忆锚点；
- Reading：收藏、阅读状态、摘要、摘录和用途；
- Inbox / Notes：快速捕捉与待整理箱；
- Course：课程扫描、转写、简报、笔记、审查和课次状态；
- Writing：Markdown 写作、资料、批注、版本和发布前检查；
- Content / Publish：栏目、合集、标签、访问模式和统一发布；
- System：模型、提醒、流水线、数据库与运行状态；
- Materials / Tools：材料处理、OCR 和辅助工具。

### 自动化与控制面

- Vercel 承载 Web/API；
- Supabase 承载业务数据、状态和加密集成配置；
- GitHub Actions 承载课程与工程自动化；
- 腾讯云承载 OpenClaw Gateway、Cloudflared 和微信 Relay；
- 微信是自然语言入口，但不能成为不受控的生产 shell。

## 当前技术边界

- Next.js 14 Pages Router + React 18；
- NotionNext compatibility 必须继续保留；
- Clerk 负责工作台身份；
- Supabase 按 `owner_id` 隔离；
- 用户级 AI 配置可以加密保存于 `user_integrations`；
- 课程链路是 durable workflow，不依赖浏览器保持打开；
- 微信 Relay 不直接访问数据库，也不调用自由 Agent 工具；
- 模型负责理解和生成受约束计划，代码负责读取真实对象和执行。

## 产品设计原则

- 内容与发布页面保持正式，不使用像注释或聊天回复的产品文案；
- 页面层级应清晰，阅读器支持折叠、固定侧边栏、目录高亮和阅读进度；
- 卡片可以有封面、轻玻璃和悬浮反馈，但不得牺牲可读性；
- Today 不做 KPI 看板，不强制连续打卡或任务耗时排名；
- 学习功能帮助理解，不强制复习计划、考前倒计时或模拟考场；
- 系统优先构建真实使用闭环，不搭空壳。
