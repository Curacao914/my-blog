# law-tech.dev 产品架构

本项目采用“对象 + 工作流”模型，而不是模块堆叠模型。

## 生长原则

新功能必须接入既有链路：

```text
Capture → Objects → Workflows → Views → Publish
```

- Capture：任何入口先进收集箱。
- Objects：沉淀为事项、材料、课程、笔记、文章、项目等对象。
- Workflows：对象进入可追踪的处理流程。
- Views：页面只是视图，不是数据孤岛。
- Publish：所有公开、密码、限时访问都由发布层统一控制。

## 工作台一级视图

- 今日：今天该处理什么。
- 收集箱：所有未判断输入。
- 进行中：正在运行的流程。
- 资料库：文件、链接、图片、引用材料。
- 课程：课程材料与笔记生产。
- 写作：选题、草稿、文章、论文材料。
- 发布：公开、密码、有效期、快照。
- 系统：模型、通知、接口、权限。

## 非目标

- 不再把新功能直接堆到首页。
- 不再让每个功能单独发明上传、权限、状态和日志。
- 不在前端暴露“worker manifest / preflight / schema”等后端语汇。
